PowerShell: running scripts is disabled on this system

Not a bug — a deliberate safety default. Here's what it's protecting against and how to loosen it just enough.

The error

Running a .ps1 script — your own, or one from an install guide (npm, nvm, a project's setup script) — fails with:

File C:\Users\you\setup.ps1 cannot be loaded because running scripts is
disabled on this system. For more information, see about_Execution_Policies
at https:/go.microsoft.com/fwlink/?LinkID=135170.

Why it happens

PowerShell's execution policy controls which scripts are allowed to run, precisely because a .ps1 file can do anything a signed-in user can do, and Windows historically made it too easy to double-click a malicious script by accident. The default policy on a standard Windows install, Restricted, blocks all script files from running — only commands typed directly into the prompt work. This isn't specific to any one script; it blocks all of them until the policy is changed.

The available levels, from most to least restrictive: Restricted (no scripts at all, the default), AllSigned (only scripts with a trusted digital signature), RemoteSigned (local scripts you wrote run freely; scripts downloaded from the internet need a signature), and Unrestricted (everything runs, with a warning for downloaded files).

Fix it

Check your current policy first:

Get-ExecutionPolicy

The generally recommended setting for development machines is RemoteSigned, scoped to your user account only (so it doesn't require admin rights and doesn't change the policy machine-wide):

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

This lets scripts you write or scripts already on your machine run freely, while still requiring a signature for anything freshly downloaded — a reasonable middle ground rather than turning the protection off entirely.

Still blocked after that? Check the file's zone

A script downloaded via a browser is tagged internally as coming from the internet, and RemoteSigned will still block it even with the policy set correctly. Check for and remove that tag on a specific file:

Unblock-File -Path .\setup.ps1

If you only need to run one script once and don't want to touch the system-wide policy at all, bypass it for that single session:

powershell -ExecutionPolicy Bypass -File .\setup.ps1

This only affects that one invocation — your saved policy (checked with Get-ExecutionPolicy) is unchanged afterward.
