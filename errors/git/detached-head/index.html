Git: you are in 'detached HEAD' state

Not an error exactly — a warning that you're not on a branch, and that any commits you make now can be hard to find again.

The message

After checking out a specific commit, tag, or a remote branch by its full ref, Git prints something like:

Note: switching to '4f2a9c1'.

You are in 'detached HEAD' state. You can look around, make experimental
changes and commit them, and you can discard any commits you make in this
state without impacting any branches by switching back to a branch.

Why it happens

Normally, HEAD is a pointer to a branch (like main), and a branch is itself a pointer to a commit — when you commit, the branch pointer moves forward automatically. Running git checkout <commit-hash>, git checkout <tag>, or git checkout origin/main points HEAD directly at a commit instead, with no branch in between. You can look around, run code, even build the project exactly as it was at that point in history — that part is completely safe. The catch is what happens if you commit while detached: the new commit exists, but no branch points to it, so the moment you check out a branch again, that commit becomes unreachable through normal Git commands and is eventually garbage-collected.

Fix it — before switching away

If you've made commits you want to keep while detached, create a real branch pointing at your current position before you check out anything else:

git switch -c my-new-branch

(or the older equivalent, git checkout -b my-new-branch). That instantly turns your detached commits into a normal branch tip, safe from garbage collection, and you can merge or push it like any other branch.

If you already switched away and think you lost commits

Nothing is deleted immediately — Git keeps unreferenced commits for a while (30 days by default) before actual garbage collection. Recover a lost commit's hash with:

git reflog

This lists every place HEAD has pointed recently, including the detached commit you were on. Find the entry, then create a branch from that hash the same way: git switch -c recovered-work <hash-from-reflog>.

If you only meant to look at old code and made no commits, there's nothing to recover — just switch back to a branch normally with git switch main and the warning goes away.
