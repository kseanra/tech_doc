Git: Automatic merge failed; fix conflicts

What a merge conflict actually is, how to read the markers Git leaves in your files, and how to finish (or bail out of) the merge.

The error

You ran git merge (or git pull, which is a fetch plus a merge) and got:

Auto-merging src/app.js
CONFLICT (content): Merge conflict in src/app.js
Automatic merge failed; fix conflicts and then commit the result.

Why it happens

Git merges automatically whenever it can figure out how to combine two branches' changes on its own — different lines, different files, or changes far enough apart in the same file. A conflict means both branches changed the same lines of the same file in ways Git can't reconcile by itself, so it stops and asks you to decide. This is expected and not a sign anything is broken; it happens constantly on any repo with more than one contributor.

Git marks every conflicted spot directly in the file:

<<<<<<< HEAD
const timeout = 3000;
=======
const timeout = 5000;
>>>>>>> feature/longer-timeout

Everything between <<<<<<< HEAD and the ======= divider is what's currently on your branch; everything between the divider and >>>>>>> branch-name is what's coming in from the branch you're merging.

Fix it

See which files have conflicts:

git status

Open each file listed under "Unmerged paths," decide what the final code should look like, and delete the marker lines themselves (<<<<<<<, =======, >>>>>>>) — Git never removes these for you, and leaving one in is a very easy mistake to ship. Once a file is resolved the way you want it, mark it resolved and continue:

git add src/app.js
git commit

Git pre-fills a merge commit message for you; you usually don't need to change it. If you have several conflicted files, resolve and git add each one before running the final git commit.

Changed your mind? Abort it

If the conflicts are extensive or you realize this merge shouldn't be happening yet, back out completely and return to exactly where you were before running git merge:

git merge --abort

This only works before you've committed the merge — once you run git commit to finish it, use git reset --hard ORIG_HEAD instead if you need to undo it (and only if you haven't pushed yet; rewriting history after a push needs a force-push and a heads-up to anyone else using that branch).
