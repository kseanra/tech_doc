Python: ModuleNotFoundError

Why "No module named 'x'" happens even right after you installed it, and how to actually fix it.

The error

Traceback (most recent call last):
  File "app.py", line 1, in <module>
    import requests
ModuleNotFoundError: No module named 'requests'

Why it happens

This is almost never "the package doesn't exist" — it's that the Python interpreter actually running your script can't see it. The most common causes, in order of likelihood:

  • You installed the package with one Python/pip, and you're running the script with a different one — very common with multiple Pythons installed (system Python, Homebrew Python, a version manager) or when a virtual environment exists but isn't active.
  • You're inside a virtual environment but installed the package before activating it, or in a different terminal tab that never activated it.
  • The import name doesn't match the package name — installing beautifulsoup4 but importing bs4 is correct and expected, but a typo in either direction produces this exact error.
  • For your own local module (not a third-party package): you're running the script from a different working directory than the one the import assumes, or a package directory is missing its __init__.py.

Fix it

First, confirm which Python is actually about to run your code:

which python
python -c "import sys; print(sys.executable)"

Install into that exact interpreter — using python -m pip instead of a bare pip avoids the classic mismatch where pip on your PATH points at a different Python than python does:

python -m pip install requests

If you're meant to be in a virtual environment, check for the (venv) prefix in your prompt before installing or running anything — if it's missing, activate it first:

# macOS / Linux
source venv/bin/activate

# Windows
venv\Scripts\activate

For a local module that isn't a third-party package, confirm you're running from the directory the import expects, and that any package directory in the path has an __init__.py file if your Python version and import style require one.

Confirm what's actually installed where

Before reinstalling anything, check whether the package is already present and exactly where:

pip show requests

If pip show succeeds but the import still fails, that confirms the mismatch is about which Python is running your script, not whether the package is installed at all — which points straight back to the "which Python" check above instead of a wasted reinstall.
