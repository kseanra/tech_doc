Node.js: EADDRINUSE

What "address already in use" means, and the fastest way to free up the port instead of guessing.

The error

You start your dev server and Node refuses to boot:

node:events:495
      throw er; // Unhandled 'error' event
      ^

Error: listen EADDRINUSE: address already in use :::3000
    at Server.setupListenHandle [as _listen2] (node:net:1740:16)
    at listenInCluster (node:net:1788:12)
    at Server.listen (node:net:1876:7)

Why it happens

Something is already bound to that port — the operating system only lets one process listen on a given port at a time. Almost always it's one of these:

  • A previous run of the same dev server is still alive — killed with an interrupt that didn't fully propagate, crashed and left an orphaned child process, or the terminal it was running in was just closed.
  • A tool like nodemon or ts-node-dev restarted your app but the old worker process didn't exit before the new one tried to bind the port.
  • A genuinely different service — another app, a Docker container publishing the same host port — is using it, unrelated to anything you're debugging.

Fix it

Find whatever's actually holding the port:

# macOS / Linux
lsof -i :3000

# Windows (PowerShell or cmd)
netstat -ano | findstr :3000

Then stop it. On macOS/Linux, kill the PID lsof printed:

kill -9 <pid>

On Windows, using the PID from the last column of netstat:

taskkill /PID <pid> /F

If it keeps coming back immediately, a process manager (nodemon, a shell script, Docker's restart policy) is probably respawning it — stop that supervisor first, not just the process it spawned.

If you don't actually care which port you use right now, it's often faster to just run on a different one instead of hunting down the old process:

PORT=3001 node server.js

When killing the parent isn't enough

A process started via child_process.spawn or a shell pipeline sometimes survives its parent being killed — you'll kill the PID you see in your terminal and the port is still held a second later. If that happens, match by command name instead of PID:

pkill -f "node.*server.js"
