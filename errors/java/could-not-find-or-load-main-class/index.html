Java: Could not find or load main class

Almost always a classpath or package-path mismatch, not a missing file. Here's how to tell which one you've got.

The error

Running a compiled program with java fails immediately with:

Error: Could not find or load main class com.example.App
Caused by: java.lang.ClassNotFoundException: com.example.App

Why it happens

The java launcher looks for your class along the classpath — the set of directories and JARs it searches — using the class's fully-qualified name translated directly into a folder path. A class declared as package com.example; must live at com/example/App.class relative to a classpath root, not just anywhere on disk. Three things cause this error almost every time:

  • Running from the wrong directory. If App.class is compiled to out/com/example/App.class, you need to run java -cp out com.example.App — pointing the classpath at out, not at the folder containing the .class file itself.
  • Package declaration doesn't match the folder structure. A file declaring package com.example; has to physically sit inside a com/example/ folder relative to the source/classpath root — Java derives the expected location from the declaration, and a mismatch here is a compile-time warning in some setups but a runtime ClassNotFoundException in others.
  • You never actually compiled it — running java App.java against a plain source file works in modern JDKs (11+) as a single-file launch shortcut, but running java App (no .java) expects a compiled App.class to already exist from an earlier javac run.

Fix it

Compile explicitly first, so you're not relying on the single-file shortcut behaving the way you expect:

javac -d out src/com/example/App.java

Then run it, setting the classpath to the compiled-output root and naming the class by its full package path:

java -cp out com.example.App

If you're not using packages at all, drop the com.example. prefix entirely — an unqualified class name only resolves if the class truly has no package declaration.

Double-check the actual location of the compiled class file against what you're telling java to look for:

find out -name "*.class"

If that path doesn't match <classpath-root>/com/example/App.class exactly, that mismatch is the bug — fix the -d output directory on javac, the -cp value on java, or the package declaration in the source, whichever one is actually wrong.
