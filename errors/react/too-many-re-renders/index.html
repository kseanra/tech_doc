React: Too many re-renders

React caught you in an infinite render loop before it could lock up the tab — here's the one-line pattern that almost always causes it.

The error

A component throws, and the browser console shows:

Error: Too many re-renders. React limits the number of renders to prevent
an infinite loop.

Why it happens

A render is supposed to be a pure calculation: React calls your component function, it returns some JSX, done. Calling a state setter (from useState) during that render — rather than in response to an event or effect — schedules another render immediately, which calls the component again, which calls the setter again, forever. React detects this pattern and throws deliberately, before the loop actually freezes the tab.

By far the most common cause is calling the setter directly in the JSX, instead of passing a function reference for React to call later:

// Bug: setCount() runs on every render, immediately re-triggering another one
return <button onClick={setCount(count + 1)}>Add</button>;

Here, setCount(count + 1) executes the instant this line runs during render — not when the button is clicked — because onClick needs to be handed a function, and this code hands it the result of calling setCount instead of the call itself.

Fix it

Wrap the call in a function so it only runs on click, not during render:

return <button onClick={() => setCount(count + 1)}>Add</button>;

The less obvious version: setting state directly in the component body

The same mistake shows up in a subtler form when a setter is called unconditionally in the component body, outside of an event handler or a useEffect:

function Panel({ isOpen }) {
  const [open, setOpen] = useState(false);
  setOpen(isOpen); // runs on every render — same infinite loop
  return <div>{open ? "open" : "closed"}</div>;
}

If the intent is to sync local state to a prop whenever it changes, that belongs in a useEffect with the prop in the dependency array (or, often better, no local state at all — just use the prop directly if nothing else needs to modify it):

useEffect(() => { setOpen(isOpen); }, [isOpen]);

Either way, the diagnostic question is the same: find every place in the component that calls a setter, and confirm each one runs only inside a handler, an effect, or a conditional — never unconditionally in the function's main body where every single render will trigger it again.
