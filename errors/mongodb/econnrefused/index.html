MongoDB: connect ECONNREFUSED

Your app can't reach a MongoDB server at all — this is a networking failure, not an authentication or query problem.

The error

Connecting with the driver, Mongoose, or mongosh fails with:

MongoServerSelectionError: connect ECONNREFUSED 127.0.0.1:27017

Why it happens

ECONNREFUSED means the operating system actively refused the connection — nothing was listening on that IP and port at all. This is a strictly earlier failure than an authentication or authorization error: MongoDB never even got the chance to check credentials, because no MongoDB process answered the connection attempt in the first place. The most common causes:

  • The mongod process isn't running — never started, or crashed after starting.
  • Wrong port — a custom --port was used to start MongoDB, but the connection string still targets the default 27017.
  • Docker networking — the classic case: your app runs in one container, MongoDB in another, and the app is still pointed at 127.0.0.1, which inside a container refers to that container itself, not the host or a sibling container.

Fix it — local (non-Docker) setup

Confirm the server is actually running and listening:

systemctl status mongod
# or, cross-platform:
ps aux | grep mongod

If it's not running, start it (via your OS's service manager, or directly with mongod --dbpath /path/to/data) and check its own startup log for why it might have failed silently — a lock file left over from an unclean shutdown, or a data directory permission problem, are both common.

Fix it — the Docker case

If MongoDB is running in a container and your app is too, 127.0.0.1 from inside the app's container will never reach a MongoDB container, because each container gets its own loopback interface, isolated from the host and from every other container. Point the connection string at the MongoDB container's service name instead — this only resolves automatically when both containers are on the same user-defined network, which Docker Compose sets up for you by default:

# docker-compose.yml
services:
  app:
    build: .
    environment:
      - MONGO_URL=mongodb://mongo:27017/mydb
  mongo:
    image: mongo:7

If your app runs on the host directly (not in a container) but MongoDB runs in a container, use localhost:27017 from the host only if you published the port with -p 27017:27017 or an equivalent ports: entry — without that mapping, the container's port is invisible from outside it entirely. This is the same underlying networking model behind the equivalent Redis connection-refused error.
