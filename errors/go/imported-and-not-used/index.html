Go: imported and not used

Not a warning — Go refuses to compile at all until every imported package is actually referenced somewhere in the file.

The error

Running go build or go run fails before your program ever executes:

./main.go:5:2: "fmt" imported and not used

Why it happens

Most languages treat an unused import as a linter warning at worst. Go treats it as a compile error, full stop — the compiler refuses to produce a binary at all. This is a deliberate language design choice, not an oversight: the Go authors wanted to eliminate the slow accumulation of dead imports that happens in large codebases in other languages, where nobody ever gets around to cleaning up an import nobody removed after refactoring. The tradeoff is that a genuinely temporary situation — commenting out the one line that used a package while debugging — breaks the build immediately, which trips up nearly everyone coming from another language for the first time.

Fix it

The direct fix is almost always right: either use the package somewhere in the file, or remove the import entirely. If you commented out the only line using fmt while debugging, either comment out the import too, or (more common in practice) use go build's companion tool to do it for you:

goimports -w main.go

goimports is a superset of gofmt that also adds missing imports and removes unused ones automatically — most Go editor integrations run it on save specifically so this error rarely surfaces during normal editing, only when running from the command line directly on a file that hasn't been through it.

When you need the import for its side effects only

Some packages are imported purely for their init() function's side effects — registering a database driver, for instance — with no exported identifier from the package ever referenced directly in your code. For this specific case, Go provides the blank identifier as an explicit "yes, I mean to import this and never reference it":

import _ "github.com/lib/pq"

The underscore tells both the compiler and the next person reading the file that the omission is intentional, rather than a genuinely stale import that should be removed.
