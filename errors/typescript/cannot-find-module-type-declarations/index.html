TypeScript: Cannot find module or its type declarations

The package is installed and your code runs fine in JavaScript — TypeScript specifically can't find type information for it.

The error

Importing a package that installed without any npm error still fails to compile:

src/index.ts:1:19 - error TS7016: Could not find a declaration file for
module 'left-pad'. '/project/node_modules/left-pad/index.js' implicitly has
an 'any' type.

or, for a module that genuinely doesn't exist anywhere on disk:

src/index.ts:2:24 - error TS2307: Cannot find module './config' or its
corresponding type declarations.

Why it happens

TypeScript needs to know the shape of every module you import — what functions it exports, what types they take and return — and that information doesn't come from the JavaScript file itself; it comes from a separate .d.ts declaration file. Some packages ship their own (look for a "types" or "typings" field in their package.json); many popular packages that don't ship their own instead have community-maintained types published separately under the @types scope on npm. TS7016 specifically means: the JS module exists and works fine, but no type declarations were found for it anywhere. TS2307 is broader and also covers a genuinely wrong import path, a file that hasn't been created yet, or a path-mapping alias in tsconfig.json that isn't set up correctly.

Fix it — missing types for a real package (TS7016)

Check whether a community types package exists and install it as a dev dependency:

npm install --save-dev @types/left-pad

If none exists for that package, you have two honest options: write a minimal ambient declaration yourself in a .d.ts file included in your project (e.g. declare module 'left-pad'; to silence the error while treating everything from it as any), or set "noImplicitAny": false in tsconfig.json — the second option is a blunt instrument that weakens type-checking project-wide, so prefer the targeted declaration.

Fix it — a local import that can't be found (TS2307)

First rule out a typo or wrong relative path — ./config vs ./Config matters on case-sensitive filesystems (Linux, and CI, even if your Mac or Windows machine is case-insensitive and hides the bug locally). If you're using path aliases (@/utils style imports), confirm both halves of the mapping exist and agree: the paths entry in tsconfig.json, and — separately — your bundler's own alias configuration (Webpack, Vite, Jest each need telling about the same alias independently; TypeScript's paths only affects type-checking, not how your bundler actually resolves the import at build time).
