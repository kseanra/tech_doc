CSS

Layout and styling patterns worth keeping within arm's reach.

grep -i
flexbox-center.css css 
/* perfectly center any child */
.container {
  display: flex;
  justify-content: center;
  align-items: center;
  min-height: 100vh;
}

The one-liner every developer eventually memorizes. Works on any container; swap min-height for a fixed height if the parent isn't full-viewport. On mobile, 100vh can measure taller than what's actually visible before the browser's address bar collapses — swap in 100dvh (dynamic viewport height) if that jump matters.

grid-areas.css css 
.layout {
  display: grid;
  grid-template-areas:
    "header header"
    "sidebar content"
    "footer footer";
  grid-template-columns: 220px 1fr;
}
.header  { grid-area: header;  }
.sidebar { grid-area: sidebar; }
.content { grid-area: content; }
.footer  { grid-area: footer;  }

Named template areas read like ASCII art of the page itself — the fastest way to reason about a layout without counting grid lines. Redefine grid-template-areas inside a media query to rearrange the same layout for mobile, and the responsive version stays just as readable as the desktop one.

custom-properties.css css 
/* define once, reuse everywhere */
:root {
  --brand: #F2A65A;
  --gap: 1.5rem;
}
.button {
  background: var(--brand);
  padding: var(--gap);
}

Custom properties cascade and can be overridden per-component or per-media-query, unlike Sass variables which are compiled away. They're also readable at runtime with getComputedStyle, so JavaScript can read or update a design token directly — a preprocessor variable no longer exists by the time the browser sees the CSS, so it can never do that.

clamp-responsive.css css 
/* fluid type: scales between a min and max based on viewport width */
h1 {
  font-size: clamp(1.5rem, 4vw + 1rem, 3rem);
}

/* fluid spacing works exactly the same way */
.section {
  padding-block: clamp(1rem, 5vw, 4rem);
}

clamp(min, preferred, max) replaces a stack of media-query breakpoints with one line — the middle value does the scaling, the outer two stop it from getting unreadably small or absurdly large. No JavaScript, no resize listener, and unlike fixed breakpoints it keeps responding smoothly if the user zooms.

container-queries.css css 
.card-container {
  container-type: inline-size;
  container-name: card;
}

@container card (min-width: 400px) {
  .card { grid-template-columns: 120px 1fr; }
}

A media query only knows the viewport's size; a container query lets a component style itself based on the size of its own container instead. The same card component can stack in a narrow sidebar and switch to a two-column layout in a wide one, with no idea what page it's sitting on.
