Footnote reference[^1]

[^1]: The footnote text, rendered at the bottom of the document.

Task lists, strikethrough, autolinks and footnotes are GitHub Flavored Markdown (GFM) extensions, not part of the original CommonMark spec. They render correctly on GitHub, GitLab, and most modern renderers, but can show up as literal text — - [ ], ~~text~~ — on a stricter parser, like some static site generators or npm's registry README renderer. Check the target before relying on them.

common-mistakes.md md 
# no blank line before a list → merges into the paragraph
This is a paragraph
- item one          ← renders as plain text, not a list

This is a paragraph

- item one           ← blank line above → renders as a real list

# nesting needs 4-space indent, not 2
- parent item
    - nested item     ← 4 spaces (or a tab) — 2 often fails to nest

# hard line break needs two trailing spaces (invisible!)
Line one
Line two              ← the two spaces after "one" force a <br>

Most "why isn't my Markdown rendering right" questions come down to one of these three: a missing blank line around a block element, under-indenting a nested list item, or expecting a single newline to break a line the way it would in plain text. Markdown collapses a lone newline into the same paragraph unless you add a hard break.

links-and-references.md md 
[inline link](https://example.com "optional title")

[reference-style link][docs]

[docs]: https://example.com/docs "optional title"

Reference-style links keep long URLs out of the sentence you're actually writing — useful when the same link is repeated many times in a doc, or when the raw URL is long enough to make the source hard to read. The reference definition can live anywhere in the file, including all grouped together at the bottom, without changing how anything renders.
