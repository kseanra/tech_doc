How this regex tester works

      
Type a pattern into the Pattern field and toggle the flags you need, then edit the text in Test string. Matches update live: each one is wrapped in a highlight below and listed with its index, full match text, and any capture groups. Matching runs inside a background Web Worker in your own browser — nothing is uploaded, and a runaway pattern can't freeze the page (see the note on backtracking below).


      
Worked example

      
The page loads with \b[\w.+-]+@[\w-]+\.[a-z]{2,}\b (flags g i) already testing against a sample sentence containing two email addresses — both highlight immediately so you can see the tool working before you type anything.


      
Flags

      
    
        
  • g — global: find every match instead of stopping at the first.
    • 
        
  • i — case-insensitive matching.
    • 
        
  • m — multiline: ^ and $ match the start/end of each line, not just the whole string.
    • 
        
  • s — dot-all: . also matches newline characters.
    • 
        
  • u — unicode mode: treats the pattern and string as a sequence of Unicode code points.
    • 
      


      
Handy patterns to try

      
    
        
  • Email: \b[\w.+-]+@[\w-]+\.[a-z]{2,}\b
    • 
        
  • URL: https?:\/\/[^\s]+
    • 
        
  • IPv4 address: \b(?:\d{1,3}\.){3}\d{1,3}\b
    • 
        
  • Hex color: #[0-9a-f]{3,8}\b
    • 
      


      
An invalid pattern shows the JavaScript engine's own error message rather than a generic failure. If a pattern is still evaluating after about 1.5 seconds against your text — a classic sign of catastrophic backtracking, e.g. (a+)+$ against a long run of "a" characters — it's cancelled automatically and flagged, instead of locking up the tab.
