How this formatter works

      
This isn't a full SQL parser — it doesn't build an abstract syntax tree or understand your schema, and it won't validate that the query is semantically correct. What it does is recognize the major clause keywords (SELECT, FROM, WHERE, the various JOIN forms, GROUP BY, ORDER BY, HAVING, LIMIT, and the DML keywords INSERT INTO, UPDATE, SET, DELETE FROM, VALUES) and break the query onto a new line before each one, indent AND/OR conditions inside a WHERE clause, and expand long comma-separated lists — a wide SELECT column list or a multi-column GROUP BY — onto their own lines. That covers the overwhelming majority of hand-written queries and works the same way across MySQL, PostgreSQL, SQLite, and SQL Server dialects, since the clause keywords are effectively identical across all of them.

      
What it won't get right

      
Because there's no real parser underneath, a keyword that appears inside a string literal or a quoted identifier (a column literally named "order", for instance) can get treated as a clause boundary it isn't. Deeply nested subqueries are formatted clause-by-clause rather than recursively indented by nesting level, so a query with several layers of subqueries will format each layer's clauses correctly but won't visually stair-step the nesting the way a full SQL-aware formatter would. For anything you're about to run against production, always re-read the formatted output before treating it as the query you're going to execute — this tool changes whitespace only, never your SQL's actual tokens, but "changes whitespace only" is still worth double-checking on a two-thousand-row UPDATE.

      
A before/after example

      
Given select u.id, u.name, o.total from users u join orders o on o.user_id = u.id where o.status = 'paid' and o.total > 100 order by o.total desc, the formatter produces a SELECT line with the three columns, a FROM line, a JOIN ... ON line, a WHERE line followed by an indented AND line, and a final ORDER BY line — the same query, considerably easier to scan when it's buried in application code or a migration file six months from now.
