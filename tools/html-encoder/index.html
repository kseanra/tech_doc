When you need to encode HTML

      
Any time user-supplied text ends up inside an HTML page — a comment, a display name, a search term echoed back on a results page — the five characters & < > " ' need to become entities (&amp;, &lt;, &gt;, &quot;, &#39;) before they're inserted. Skip that step and a comment containing <script> or an onerror= attribute isn't just displayed wrong — it executes, which is the root cause of stored cross-site scripting (XSS) vulnerabilities. This tool does the encoding side of that safely; it does not replace a proper templating engine's auto-escaping in production code, but it's useful for manually preparing a snippet, checking what a string will render as, or reverse-engineering a page that already has encoded content in its source.

      
Why the decoder uses a hidden textarea instead of parsing HTML

      
A tempting shortcut for decoding entities is to set a string as an element's innerHTML and read back its textContent — but that means asking the browser to parse arbitrary HTML, and if the input contains a real tag with an event handler, some code paths can still trigger it. This tool instead assigns the input to a <textarea> element's innerHTML: a textarea's content is always treated as plain text data by the HTML parser, never as markup, so entities inside it resolve correctly (both named entities like &amp; and numeric ones like &#233;) while any literal <tag> in the input stays inert text rather than becoming a live element. It's the same trick browsers themselves rely on internally, and it never touches the visible page or the network.

      
Encoding non-ASCII text

      
Modern pages served as UTF-8 don't strictly need accented letters or emoji encoded as entities — the browser renders them directly. The checkbox above exists for the cases where you don't control the destination's encoding: pasting into an older CMS, an email template, or a system that mangles anything outside plain ASCII. With it ticked, every character above code point 127 is converted to its &#NNN; numeric form, which is guaranteed to survive regardless of the receiving system's character set.
