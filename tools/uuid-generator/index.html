About version-4 UUIDs

      
A v4 UUID is a 128-bit identifier built almost entirely from random bits (122 of them — the other 6 are fixed, to mark the version and variant), formatted as xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx. The 4 marks the version, and the leading digit of the next group (y) is constrained to one of 8, 9, a, or b so the value is recognizable as a valid UUID by anything that parses it.

      
How unlikely is a collision, really?

      
With 122 random bits, the number of possible v4 UUIDs is roughly 5.3 × 1036. To put that in perspective: you'd need to generate around a billion UUIDs per second for about a hundred years before the odds of any two ever matching reached even one in a billion. In practice this means you can generate v4 UUIDs independently on any number of machines, with no coordination between them, and treat collisions as effectively impossible for any real-world system.

      
What this tool uses under the hood

      
Generation happens via the browser's built-in crypto.randomUUID(), which draws from the operating system's cryptographically secure random number generator — the same quality of randomness used for generating encryption keys, not the weaker, predictable kind behind Math.random(). That matters if a UUID is ever used somewhere its unguessability is actually load-bearing (a password-reset token, an unlisted share link), rather than purely as a unique label.

      
When a UUID is the wrong choice

      
Because v4 UUIDs are pure randomness, they're deliberately unordered — generating ten in a row tells you nothing about the sequence they were created in, and using them as a database primary key can hurt insert performance on engines that store rows in primary-key order, since each new random UUID lands in an arbitrary spot in the index rather than appending at the end. If you need IDs that are both unique and roughly sortable by creation time, look into UUID v7 (time-ordered, standardized more recently) or a library implementing ULID/Snowflake-style IDs instead — this generator intentionally sticks to the widely-supported, purely-random v4 format.
