XML Formatter & Validator

What "well-formed" means, and why it's checked first

      
XML has one hard requirement that HTML famously doesn't: every element you open has to be closed, tags can't cross each other (<a><b></a></b> is invalid), attribute values must be quoted, and there has to be exactly one root element wrapping everything else. A document that breaks any of these rules is not "loosely formatted XML" — it isn't XML at all, and any real XML parser (in your language's standard library, in a build tool, in whatever system is meant to consume the file) will reject it outright. This tool uses the browser's own built-in DOMParser to attempt a real parse before doing anything else, so if the input is broken, you get a specific parser error — typically naming the line and the mismatched or unclosed tag — instead of a formatter silently producing nonsense from invalid input.

      
How the pretty-printer works

      
Once the document parses cleanly, formatting is done by inserting a line break at every tag boundary and then indenting each line two spaces deeper each time a new element opens, and two spaces shallower each time one closes — the same visual convention used by xmllint --format and most IDE "reformat XML" commands. Self-closing tags (<br/>) and elements that open and close on the same line (<name>Alex</name>) don't affect the indent level, so the structure that comes out mirrors the document's actual nesting rather than an arbitrary re-flow. Minify does the opposite: it strips all whitespace between tags, which is useful when you need to paste XML into a context — a config value, a single-line log field — that can't contain literal newlines.

      
What this tool doesn't do

      
It checks well-formedness, not validity against a schema — a document can be perfectly well-formed XML while still violating an XSD or DTD that defines which elements and attributes are allowed where. It also doesn't resolve external entities or DOCTYPE declarations that reference outside files, both by design: pulling in external resources from a document you paste into a browser tool is exactly the kind of behavior (XXE) that makes XML parsers a security liability when handled carelessly, so this tool sticks to parsing the document exactly as given.
