What a Unix timestamp is

      
A Unix timestamp (also called epoch time) is the number of seconds that have elapsed since 00:00:00 UTC on 1 January 1970, ignoring leap seconds. It's the internal representation most systems use for "a point in time" because it's a single integer that sorts, compares, and does arithmetic naturally — no timezone, no calendar, no daylight saving to reason about until you're ready to display it to a person. Log files, database created_at columns, JWT exp/iat claims, and API responses across almost every backend language store time this way internally, even when they render it as a human-readable date on the way out.

      
Seconds vs. milliseconds — the most common mix-up

      
Unix time is defined in seconds, but JavaScript's Date.now() and new Date().getTime() return milliseconds since the epoch, while most server-side languages (Python's time.time() aside, which also returns seconds as a float) and most database and API conventions use seconds. Mixing the two up is one of the most common timestamp bugs there is: feed a millisecond value into a function expecting seconds and you'll get a date sometime in the late 1970s (a value 1000x too small reads as far too early); feed a second value into something expecting milliseconds and you'll land in 1970 itself. Both values are shown above, live, specifically so you can sanity-check which one a system in front of you is actually emitting — paste a timestamp you're debugging next to these and see which column it's closer to in digit count (ten digits is seconds, thirteen is milliseconds, for dates anywhere near today).
