JWT Decoder

Paste a JSON Web Token to see its decoded header and payload. Decoding happens locally — the token is never sent anywhere, and the signature is not verified.

This tool only decodes the token (it base64url-decodes the header and payload). It does not verify the signature — a JWT can be decoded by anyone without the secret/private key, but only the issuer can produce a validly signed one.

What is a JWT?

      
A JSON Web Token is three Base64url-encoded segments joined by dots: header.payload.signature. The header names the signing algorithm and token type; the payload carries the claims — the actual data the token asserts, like who it's for and when it expires; and the signature is a cryptographic value computed over the header and payload together, which lets a server holding the matching secret (or public key, for asymmetric algorithms) confirm neither segment has been altered since the token was issued.

Everything beyond these is application-specific — roles, permissions, an email address, whatever the issuer chose to include.

      
Why "decoded, not verified" is the important distinction

      
Base64url is an encoding, not encryption — anyone can decode a JWT's header and payload with nothing more than a text editor and a bit of patience, secret key or not. What the secret key actually protects is the signature: whether this specific header+payload combination was really produced by the issuer, or tampered with afterward. This tool deliberately only decodes; it never checks the signature, because doing that correctly requires the issuer's secret or public key, which isn't something a generic browser tool should ask you to paste in. Never treat a JWT's claims as trustworthy just because you were able to read them here — a token's contents are only meaningful once its signature has been verified against the correct key, on the server side, using a proper JWT library.

      
What this tool is actually useful for

      
Despite not verifying anything, decoding is genuinely useful for debugging: confirming an exp claim is set to the value you expected, checking which algorithm a third-party API issues tokens with, or inspecting what claims your own auth service is actually putting into a token during development — all without needing the signing key at hand.
